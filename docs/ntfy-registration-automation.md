# ntfy登録・権限設定の自動化

Node.js＋自前ntfyを維持し、運用者が端末ごとにユーザー作成・トピックの読み取り許可・解除を実行する方式から移行します。ランダムな`up...`トピック名は維持します。利用者の報告でVPSのHTTPS疎通・証明書更新試験・通知テストは成功しました。配布向けの登録自動化は、以下の段階で別途進めます。

## 段階と完了条件

1. **ntfy管理操作の基盤（今回）**：サーバー内の管理アダプターを作り、ntfy 2.32.0の一時DBで、一般ユーザーの作成・単一トピックの読み取り許可・解除・削除を検証します。既存APIとAndroidからはまだ呼びません。既存VPSのユーザーやACLは変更しません。
2. **認証済みAPIと永続化**：端末UIDとntfyユーザー・資格情報・トピック所有者を束縛し、状態と管理ジョブを永続化します。作成・通知先更新・停止・削除の再試行と再起動時の復旧を実装します。別端末のトピックの横取り・重複割当てを拒否し、所有確認までは募集を送信しません。
3. **Androidの登録画面**：発行結果と接続先を表示し、ntfy設定を案内します。ランダムなトピック名を運用者へ渡す操作はなくします。停止・削除は端末で先に抑止し、サーバー未反映と完了を分けます。
4. **VPSでの結合確認**：専用のローカル管理プロセスを配置し、実ntfyとAndroidで登録・通知先変更・解除・再起動・権限失効を確認します。配布可否はこの確認後に判断します。

第1段階だけでは新規利用者の登録は自動化されません。既存の`device001`と手動ACLは維持されます。自動移行や自動削除は行いません。

## 第1段階の管理操作

`server/ntfy-admin.ts`は、信頼されたサーバー内の呼び出し元にだけ使う部品です。HTTP API・管理用公開エンドポイント・ntfy DBの直接SQL編集は追加しません。

- 端末認証が発行したUUIDから専用の`sur_...`ユーザー名を決定し、任意のユーザー名や管理者名を入力させません。
- パスワードは256bitのランダム値を生成します。呼び出し元は生成結果を保存してから作成を依頼し、再試行では同じ値を使います。既存ユーザーのパスワードは作成の再送で変更しません。保管・認証済み端末への返却は第2段階です。
- 作成するロールは`user`のみ。許可するのは指定した`up...`トピック1件への`read-only`のみです。ワイルドカード・URL・制御文字を受け付けず、匿名・全ユーザー・全トピックへの許可は操作できません。トピックが本人のものかの束縛は第2段階の責務です。
- 解除はユーザーとトピックを指定して行います。アカウント削除も専用ユーザー1件に限定し、存在しないユーザーの再削除は完了として扱います。
- 実行ファイルと設定ファイルは運用者が設定する絶対パスに固定し、シェルを使わず引数配列で実行します。実行時間・出力サイズを制限し、CLIの生の出力をAPIエラーやログへ渡しません。
- パスワードは`NTFY_PASSWORD`環境変数で子プロセスへ渡し、引数には含めません。親の`NTFY_*`変数は引き継がず、別DBやハッシュへの意図しない上書きを防ぎます。同一OSユーザー・rootからの環境参照を防ぐものではありません。

CLIがntfyの認証DBへアクセスするため、後続段階ではntfy用ユーザーで動く限定管理プロセスへ分離します。Node.jsのAPIサービスへroot権限や無制限のsudo権限を与えたり、認証DBを公開領域へ置いたりしません。現在のsystemd定義は変更しません。

## 利用者の初回操作

Google Play版・F-Droid版のntfyを利用できます。自前サーバーへの配送ではGoogle Play版もFirebaseを使いません。ntfyアプリ自身のサーバー・ログイン設定を他アプリから自動投入できる公開方式は、今回確認できた範囲では見つかっていません。初期の配布版ではntfyの導入と初回ログインは利用者が行う前提で、サーバー側のユーザー発行とACL設定を自動化します。完全な無操作登録とは区別します。

## 検証

```sh
pnpm exec vitest run tests/ntfy-admin.test.ts
```

実際のntfyバイナリーを使う結合テストはLinuxで行います。公式配布物とチェックサムを確認し、検証用バイナリーの絶対パスを指定します。テストが一時ディレクトリーへ専用設定・認証DBを作るため、本番の設定・DBは使いません。

```sh
SURENECO_TEST_NTFY_BIN=/absolute/test/ntfy pnpm exec vitest run tests/ntfy-admin.integration.test.ts --maxWorkers=1
```

指定しなければ実バイナリーのテストはスキップします。API接続・Android自動同期・VPS配備・実配送の自動化完了をこのテストだけで判断しません。

2026/10/23に公式チェックサムと照合したntfy 2.32.0で検証しました。単体テスト8件と実バイナリーの結合テスト1件が成功し、別ユーザー・別トピックへのアクセス拒否、書き込み拒否、権限解除とユーザー削除の反映を確認しました。`pnpm test:server`でも管理アダプターのテストを実行します。
