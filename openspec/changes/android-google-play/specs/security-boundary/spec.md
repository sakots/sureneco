# Androidと通知サーバーの操作権限

## ADDED Requirements

### Requirement: Androidで利用できる操作の制限

Android版は既存の通信先制限と引数検証を保ち、認証済みの固定通知APIとの通信、プッシュ受信、クリップボード、検証済みURL起動、専用領域保存に必要な権限だけを使わなければならない（SHALL）。実行ファイル起動・選択、保存先変更、GitHub更新はバックエンドでも拒否し、端末の監視用Foreground Serviceや共有ストレージ全体への権限を要求しない。

#### Scenario: 専用操作の拒否

- **WHEN** AndroidのWebViewからデスクトップ用実行ファイルの起動または保存先変更を直接要求する
- **THEN** 保存済み設定があっても拒否し、任意プロセスや外部ファイルへアクセスしない

#### Scenario: 最小権限での起動

- **WHEN** Android版をインストールして起動する
- **THEN** 端末監視の常駐サービスや共有ストレージ権限を要求せず、通知権限の拒否で終了しない

### Requirement: 通知登録APIの認証と所有者制限

通知サーバーは端末の認証と公開用アプリの検証を行い、所有者本人の購読だけを読取・更新・停止・削除させなければならない（SHALL）。通知先トークンを認証として使わない。入力上限・レート制限・正規表現の実行上限を設け、任意URLへの取得や利用者からの通知本文指定を許可しない。

#### Scenario: 他端末の設定操作

- **WHEN** 認証のない要求または別端末の購読を指定する要求が届く
- **THEN** 内容を開示・変更せず拒否し、要求された配送先へ通知しない

#### Scenario: 上限超過と重い正規表現

- **WHEN** 過大な登録や時間上限を超える正規表現が要求される
- **THEN** 制限または購読エラーとして扱い、他の利用者の監視を停止させない
