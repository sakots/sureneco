# Androidのサーバー監視

## ADDED Requirements

### Requirement: Androidの監視をサーバーで継続する

Androidの購読が有効な間は、サーバーが端末の表示状態に関係なく監視を継続しなければならない（SHALL）。サーバーの実行頻度と更新周期はpush-monitoringの「常駐サーバーの監視と更新周期」に従い、募集検出、NGと許可ワッチョイ、締め、期限を購読ごとに適用する。非表示化を理由に通知基準を更新・消去しない。PC版のローカル監視と20秒の更新下限は変更しない。

#### Scenario: 非表示中の監視

- **WHEN** 購読を有効にしたAndroid端末で別アプリへ切り替えるか画面を消す
- **THEN** サーバーは同じ通知基準で監視を続け、条件に一致する新規募集を配信対象にする

#### Scenario: デスクトップ版の継続

- **WHEN** WindowsまたはUbuntu版をトレイへ隠す
- **THEN** 従来のローカル監視と通知を継続する

### Requirement: Androidの表示更新と通知を分離する

Androidで一覧を表示・更新するために端末が直接取得しても、OS通知の発行元はプッシュ配信に統一しなければならない（SHALL）。非表示中は端末の定期取得を止め、再表示時にサーバーの取得基準をリセットしたり既存レスを一括再通知したりしない。

#### Scenario: 表示中の二重通知防止

- **WHEN** 同じ募集を表示更新とプッシュ配信の両方で受け取る
- **THEN** 一覧へ表示し、OS通知は重複させない

#### Scenario: 再表示後の継続

- **WHEN** 非表示中に募集を受け取り、その後Androidアプリを再表示する
- **THEN** 画面を更新するが、受信済み募集を新しい募集として再通知しない
