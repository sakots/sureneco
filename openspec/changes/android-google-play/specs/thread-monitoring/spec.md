# Androidの監視ライフサイクル

## ADDED Requirements

### Requirement: Androidで表示中だけ監視する

Android版はアプリが表示中のときだけ自動・手動の板取得と募集通知を行わなければならない（SHALL）。別アプリへの切り替え・画面消灯・終了時は新しい取得を開始せず、進行中の取得が完了しても非表示中は通知しない。デスクトップ版の非表示時の監視は変更しない。

#### Scenario: 非表示中の停止

- **WHEN** Android版で別アプリへ切り替えるか、画面を消す
- **THEN** 新しい取得を停止し、進行中の取得結果からも募集を通知しない

#### Scenario: デスクトップ版の継続

- **WHEN** WindowsまたはUbuntu版をトレイへ隠す
- **THEN** 従来どおり監視と通知を継続する

### Requirement: Androidの監視再開基準

Android版は表示状態へ戻ると現在のレス番号を通知基準にし直し、非表示中のレスをまとめて通知せず、新たな監視期間を開始しなければならない（SHALL）。同じ再開イベントの重複で監視ループを増やさない。再開時に取得が失敗した場合は通知を抑制したまま基準取得を再試行する。

#### Scenario: 復帰と重複防止

- **WHEN** 非表示中に複数の募集が投稿された後、Android版を再表示する
- **THEN** 非表示中の募集は通知せず、その後の新規募集だけを通常の通知条件で通知する

#### Scenario: 再開時の取得失敗

- **WHEN** 再表示時の通知基準の取得に失敗する
- **THEN** エラーを表示して次の周期に基準取得を再試行し、基準取得が成功するまで募集を通知しない
