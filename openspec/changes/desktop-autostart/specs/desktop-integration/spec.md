# デスクトップ自動起動の仕様差分

## MODIFIED Requirements

### Requirement: 常駐アプリとメニュー

アプリは以下の構成と常駐動作を提供しなければならない（SHALL）。

標準のアプリケーションメニュー（File・Edit等）は開発時・配布版とも表示しない。トレイの操作メニューは利用できる。

Windows / Ubuntuで5chの雀魂スレッドを監視するTauri 2アプリ。RustとReact / TypeScript、pnpmで開発する。既存のTypeScriptコアは専用スレッド上のQuickJSで実行し、WebViewの非表示・タイマー抑制に依存せず監視する。スレッド一覧、募集一覧、設定を一つのウィンドウで表示する。監視するスレッドは個別のトグルで選ぶ。ウィンドウを閉じるとトレイに常駐し、トレイから再表示・終了できる。トレイを作成できない環境ではウィンドウを閉じると終了する。Linuxのデスクトップエントリーはsureneco.desktopとする。ログイン時の自動起動は利用者が設定画面から選択できる。

#### Scenario: トレイがある環境で閉じる

- **WHEN** トレイを作成できる環境でウィンドウを閉じる
- **THEN** ウィンドウを非表示にして監視を継続し、トレイから再表示・終了できる

#### Scenario: トレイを作成できない環境

- **WHEN** トレイを作成できない環境でウィンドウを閉じる
- **THEN** アプリを終了する

#### Scenario: 標準メニュー

- **WHEN** 開発版または配布版のウィンドウを表示する
- **THEN** File・Edit等の標準メニューを表示しない

## ADDED Requirements

### Requirement: ユーザー単位の自動起動設定

Windows／Linux版は設定画面に「ログイン時に自動起動する」を提供し、現在のユーザーだけに適用しなければならない（SHALL）。未登録ならオフとし、インストールや初回起動だけで有効にしてはならない（MUST NOT）。状態はOSの登録から読み取り、監視条件の保存・設定フォルダ変更と独立させる。Androidには表示せず、通知サーバーへ送信しない。

#### Scenario: 有効化と再起動

- **WHEN** 利用者が自動起動をオンにし、アプリを終了して次回ログインする
- **THEN** 現在のアプリが起動して保存済み条件で監視を開始し、設定画面もオンを示す

#### Scenario: 無効化

- **WHEN** 自動起動をオフにして次回ログインする
- **THEN** このアプリの自動起動登録が解除され、他のアプリの登録は変更されない

#### Scenario: 初回起動と設定フォルダ変更

- **WHEN** 自動起動が未登録で起動する、または監視設定の保存先を変更する
- **THEN** 未登録を勝手にオンにせず、保存先変更によって自動起動状態を変更しない

#### Scenario: Androidの設定

- **WHEN** Android版で設定画面を開く
- **THEN** 自動起動設定を表示せず、自動起動のデスクトップ操作を呼び出さない

### Requirement: 自動起動の正確な反映と失敗表示

自動起動設定は登録先の読み書き失敗を利用者へ表示し、失敗を成功と報告してはならない（MUST NOT）。登録の有無だけでなく現在の実行先を確認し、別の実行先を現在のアプリの有効な登録と偽らない。変更中の多重操作を防ぎ、登録先に競合する第三者の内容がある場合は無断で上書き・削除しない。

#### Scenario: 書き込み権限がない

- **WHEN** 登録・解除に必要なOS設定の書き込みに失敗する
- **THEN** 失敗を表示し、要求した状態へ切り替え済みと表示しない

#### Scenario: 状態読み取りの失敗

- **WHEN** OS登録の状態を読み取れない
- **THEN** 未確認とエラーを表示し、オフと決めつけない

#### Scenario: 登録先の競合

- **WHEN** このアプリ用の登録名に所有を確認できない別内容が存在する
- **THEN** 競合として利用者へ表示し、第三者の登録を変更しない

### Requirement: 配布形態に応じた安全な起動

自動起動登録は現在の配布アプリの永続的な実行先を使い、空白・日本語・引用符などを安全に扱わなければならない（SHALL）。AppImageでは一時展開先を登録しない。自動起動でも通常のウィンドウ表示と既存の単一起動を維持する。実行ファイルを移動・削除すると登録が無効になり得ることを説明する。

#### Scenario: 空白を含むポータブル版

- **WHEN** 空白・日本語を含む場所のWindowsポータブル版で自動起動を有効にする
- **THEN** シェルコマンドとして解釈せず、その実行ファイルだけを起動する登録を作る

#### Scenario: Linux配布形式

- **WHEN** DEB版またはAppImage版で自動起動を有効にする
- **THEN** DEBのインストール先または元のAppImageを登録し、一時マウント先は登録しない

#### Scenario: 起動済みアプリ

- **WHEN** 自動起動と手動起動が重なる
- **THEN** 監視プロセスを増やさず、既存の単一起動・ウィンドウ再表示動作を維持する
