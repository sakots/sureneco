# Design

## Context

動機はproposal.md参照。desktop-integrationの現行仕様は自動起動を対象外としているため、この変更で明示的に対象へ追加する。`desktop.rs`はsingle-instanceとdesktop限定invokeハンドラーを持ち、Reactの`main.tsx`は描画後に`show_main_window`を呼ぶ。設定画面は`!api.mobile`でPC専用カードを分離している。WindowsのwinregとRustのdirsは既存依存で、自動起動プラグインは入っていない。

## Goals / Non-Goals

**Goals:** OS登録を正本にしてユーザー別の自動起動状態を読み書きし、共通の募集設定とモバイル同期を変更せずに提供する。

**Non-Goals:** 自動非表示起動、管理者権限、Windowsサービス、systemdサービス、他アプリの登録の管理、ポータブル版の移動追跡、自動移行。

## Decisions

### 1. 小さなdesktop専用RustモジュールにOS登録を閉じ込める

`src-tauri/src/desktop/autostart.rs`を追加し、OS別処理をcfgで分ける。WindowsはHKCUの`Software\\Microsoft\\Windows\\CurrentVersion\\Run`に専用値`sureneco`を登録する。Linuxは`$XDG_CONFIG_HOME/autostart/sureneco.desktop`（未指定なら`~/.config/autostart/`）へ専用Desktop Entryを作る。現在のユーザーのみを対象とし、全ユーザー登録は扱わない。Windowsのコマンド行とDesktop Entry Execは別形式なので個別にエスケープする。Linuxでは引用符・バックスラッシュ・予約文字・リテラルの%を仕様に従って扱い、改行やNULを実行先に許可しない。

Tauri autostartプラグインの追加も可能だが、既存winregを再利用すると依存を増やさずに対象ファイルと所有確認を制御できる。汎用OS設定フレームワークは導入しない。

### 2. OS設定が正本

共通`Settings`やstate.jsonに自動起動のbooleanを二重保存しない。状態はenabled／disabled／errorを区別し、エラーをfalseへ丸めない。登録内容が現在の実行先と一致する場合のみ有効とする。専用登録に所有を確認できない内容やシンボリックリンクがある場合は競合として拒否し、上書き・削除しない。同じアプリの既知形式でも別の実行先なら不一致として案内し、勝手に付け替えない。Linuxの書き込みは同じディレクトリーの一時ファイルから安全に置換し、既存内容と所有を更新直前にも確認する。

### 3. 実行先を配布形式ごとに決める

WindowsとLinux DEBは現在の実行ファイルの絶対パスを使う。Linux AppImageは`APPIMAGE`が示す元の実行可能ファイルを使い、一時的なAppDir内のcurrent_exeを登録しない。実行先が存在しない、絶対パスでない、実行不能などの場合は登録を拒否する。監視用の引数やshellを介さず通常起動するため、既存のウィンドウ表示・トレイ・通知クリックの振る舞いを変えない。開発ビルドからのOS登録は許可せず、未対応の理由を設定画面に表示する。実起動試験は配布相当のreleaseビルドで行う。

### 4. 型付きのdesktop APIとPC専用カード

`Api`にdesktop専用の任意オブジェクトを追加し、状態取得とbooleanでの設定変更を提供する。既存の設定保存とは独立したカードを`App.tsx`のPC分岐に置く。初期取得中・変更中は操作不可にし、変更成功時はOSから再取得した状態を表示する。失敗はエラーを表示して再照会し、直前の表示を要求値だけで切り替えない。入力はRustでもbooleanとして検証する。モバイルAPI実装にはオブジェクトを与えず、AndroidのRustバックエンドへ新しい操作を登録しない。

### 5. 解除と導入時の扱い

インストール・アップデートで利用者の同意なく登録しない。Windows NSISの通常アンインストールでは、現在のインストール先を指す自分のRun値だけを解除し、アップデート時は保持する。Linux／ポータブル版は削除・移動前に設定をオフにする手順を案内する。Linuxのパッケージ削除スクリプトから他ユーザーのホームを走査しない。

## Risks / Trade-offs

- OSで無効化・改変される → 読み取り時に実登録を確認し、一般的なログイン項目管理やWindowsのポリシーを上書きしない。登録が正しくてもOS側の起動抑止を解除できるとは保証しない。
- ポータブル版／AppImageの移動 → 固定パスという制約を説明し、移動前の解除と移動後の再登録を案内する。
- Linuxのデスクトップ環境差 → XDG Autostart対応のUbuntu GUIセッションを検証対象とし、ログイン前や非GUI環境での起動は保証しない。
- 登録ファイル・レジストリのアクセス拒否 → 成功表示にせず、元の登録と他アプリを保護する。
- 自動起動時に画面が開く → 現在の通常起動を維持する意図的な選択であり、トレイだけの起動設定は追加しない。

## Migration Plan

旧データの移行は不要。機能追加だけで登録は発生せず、設定画面の操作で初めて変更する。ロールバック前には設定をオフにする。登録の解除後も監視設定と取得基準を消さない。
