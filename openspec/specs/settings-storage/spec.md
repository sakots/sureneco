# 設定と保存先

## Purpose

監視、募集検出、NGと通知許可の設定項目、入力制約と保存方法を定義する。設定フォルダの変更を再起動なしで反映し、破損や保存先の消失時に既存データを上書きしない条件を扱う。

## Requirements

### Requirement: 期間と更新間隔の初期値

期間と更新間隔は以下の項目、範囲と初期値を提供しなければならない（SHALL）。

- update_sec: 友人戦募集の更新間隔。20以上の整数。既定20。設定画面で変更できる。保存済みの値は維持する。
- thread_update_sec: スレッド一覧の更新間隔。20以上の整数。既定300。未設定の場合は既定値を使う。
- elapsed_days: 候補のスレ立てからの経過日数。1以上の整数。既定14。
- emphasis_sec: 新しい募集とみなす秒数。1以上の整数。既定600。

#### Scenario: 更新間隔の入力

- **WHEN** 募集または一覧の更新間隔に20未満の値または整数でない値を指定する
- **THEN** 設定を拒否する

#### Scenario: 既存設定の維持

- **WHEN** 保存済みの更新間隔があり、一覧更新間隔は未設定である
- **THEN** 保存済みの募集更新間隔を維持し、一覧更新間隔には300秒を使う

### Requirement: 正規表現の初期値

検出用の正規表現は以下の初期値を提供しなければならない（SHALL）。

- thread_title_regex: 既定 `雀魂|じゃんたま|ジャンタマ|mahjongsoul|majsoul`。
- ng_thread_title_regex: 既定空。
- yujinsen_regex: 既定 `友人戦|友人部屋|(?:募集|部屋)[\s:：]*[0-9０-９]{5,6}|[0-9０-９]{5,6}[\s　]*(?:募|＠|@)|四東|四南|三東|三南|三人半荘|四人半[荘莊]|(?<![0-9０-９IVXLCDMⅠ-Ⅻⅰ-ⅻ])(?:[34３４]|III|IV|Ⅲ|Ⅳ)[東南]`。
- closed_yujinsen_regex: 既定 `〆|締め|しめ|締切|締め切|解散|埋まり|満員`。

#### Scenario: 初期状態のスレッド検索

- **WHEN** 初期設定で「雀魂」を含むタイトルを判定する
- **THEN** 検索正規表現に一致し、空の除外正規表現によって除外されない

### Requirement: 板URLとNG・通知許可の設定

板URLと投稿者のフィルターは以下の項目と制約を提供しなければならない（SHALL）。

- url: 既定 [https://egg.5ch.io/mj/] 。
- ng_words / ng_ids / ng_watchois: NG本文・ID・ワッチョイの文字列配列。
- allowed_watchois: 通知を許可するワッチョイの文字列配列。既定は空。一行に一件入力し、前後の空白・空行・重複を除く。最大1000件・一件500文字。

#### Scenario: 通知許可リストの整形

- **WHEN** 通知許可ワッチョイを空白・空行・重複を含む複数行で入力する
- **THEN** 前後の空白・空行・重複を除いて保存する

### Requirement: 設定値の検証

設定は以下の制限を保存前に検証しなければならない（SHALL）。

数値設定の上限は2147483。正規表現は1000文字まで、NGは各1000件・一件500文字まで。不正な値・正規表現は保存前に拒否する。

#### Scenario: 不正な設定

- **WHEN** 数値の上限超過、不正な正規表現またはリストの制限超過を含む設定を保存する
- **THEN** 保存前に拒否する

### Requirement: 永続化と既定保存先

保存データは以下の配置と破損時の保護条件を守らなければならない（SHALL）。

state.jsonに設定、監視対象、取得済みレス番号を一時ファイルからの置き換えで保存する。既定の設定フォルダはWindowsではAPPDATA/sureneco、LinuxではXDG_CONFIG_HOME/sureneco（未指定なら~/.config/sureneco）とする。破損した保存ファイルまたは保存先指定は上書きせず、起動時にエラーダイアログを表示して終了する。募集履歴はメモリ内だけに保持する。保存済み設定にallowed_watchoisがない場合は空として読み込み、既存の設定と監視対象を維持する。

#### Scenario: 破損した保存ファイル

- **WHEN** 起動時に保存ファイルまたは保存先指定が破損している
- **THEN** ファイルを上書きせず、エラーダイアログを表示して終了する

### Requirement: 保存先の指定と切り替え

保存先は以下の操作とデータ保護条件で切り替えなければならない（SHALL）。

設定画面に現在の保存先を表示し、絶対パスの入力またはフォルダ選択ダイアログで指定・変更できる。「保存先を変更」を押すと現在の設定・監視対象・取得済みレス番号を新しいフォルダへ保存し、以後の保存先を即座に切り替える。募集履歴と監視は継続し、再起動は不要。移動元のstate.jsonは削除しない。移動先に既存のstate.jsonがある場合は上書きせず拒否する。同じフォルダの指定は変更なしとする。ウィンドウ状態と更新用データはこの変更の対象外。

#### Scenario: 保存先変更の成功

- **WHEN** 既存のstate.jsonがない別の絶対パスのフォルダへ保存先を変更する
- **THEN** 設定・監視対象・取得済みレス番号を保存し、募集履歴と監視を継続したまま再起動なしで切り替える

#### Scenario: 既存データの保護

- **WHEN** 変更先にstate.jsonが既に存在する
- **THEN** 上書きせず保存先変更を拒否する

### Requirement: 保存先指定の記録

保存先の指定は以下の再起動と記録失敗の条件で扱わなければならない（SHALL）。

保存先の指定は既定フォルダのconfig-location.jsonに保存し、次回起動時も使用する。保存先の記録に失敗した場合は従来の保存先を使い続ける。

#### Scenario: 保存先記録の失敗

- **WHEN** config-location.jsonへの保存先の記録に失敗する
- **THEN** 従来の保存先を使い続ける

### Requirement: 指定保存先が利用できない場合

指定済み保存先の障害は以下の条件で扱わなければならない（SHALL）。

指定済みの設定フォルダが存在しない、フォルダではない、またはアクセスできない場合は起動時にエラーとし、既定値で起動しない。実行中に指定先が削除された場合も保存は失敗とし、フォルダを勝手に作り直さない。

#### Scenario: 起動時に保存先がない

- **WHEN** 指定済みフォルダが存在しない、フォルダでない、またはアクセス不能である
- **THEN** 起動エラーとし、既定値で起動しない

#### Scenario: 実行中に保存先が削除される

- **WHEN** 実行中に指定先が削除され、その後に保存する
- **THEN** 保存を失敗とし、フォルダを勝手に作り直さない
