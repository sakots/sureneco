# ルームID操作と雀魂の起動

## Purpose

募集カードからルームIDをコピーし、保存済みのブラウザーまたは指定アプリで雀魂を開く操作を定義する。コピー時のレス番号表示、起動設定の扱いと起動直後の失敗の通知を含む。

## Requirements

### Requirement: 操作結果のレス番号

コピーと起動の成功メッセージは以下の参照番号を使わなければならない（SHALL）。

コピー成功時と雀魂の起動成功時の上部メッセージは「レス 番号：ルームID …」の形式とし、本文に「>>番号」「＞＞番号」がある場合は最初の参照番号を半角で表示する。参照指定がない場合は操作した募集カードのレス番号を表示する。本文中のルームIDと参照先から得たルームIDのどちらの操作にも適用する。コピーする内容はルームIDのままとし、カード上部の番号と「レスを開く」の対象は操作したカード自身のレスとする。

#### Scenario: 本文の最初の参照番号

- **WHEN** 本文に複数の「>>番号」または「＞＞番号」がある募集を操作する
- **THEN** 最初の参照番号を半角で成功メッセージに表示し、カードと「レスを開く」の対象は変更しない

#### Scenario: 参照番号がない場合

- **WHEN** 本文にレス参照がない募集を操作する
- **THEN** 操作した募集カード自身のレス番号を成功メッセージに表示する

### Requirement: 5桁のルームIDのコピー

ルームIDの表示とコピーは以下の条件を満たさなければならない（SHALL）。

募集本文の独立した5桁の数字をクリック可能なルームIDとして表示する。参照先から取得したIDは「参照先のルームID」として表示し、同じ操作でコピーできる。レス参照番号はコピーボタンにしない。半角・全角に対応し、6桁以上の数値の一部は抽出しない。複数のIDはそれぞれクリックできる。クリックすると先頭のゼロを保持した半角5桁をクリップボードにコピーし、完了を画面に表示する。失敗時はエラーを表示する。コピー操作でブラウザーは開かない。該当レスは別の「レスを開く」ボタンから開く。コピーは限定されたTauriコマンドからバックエンドで5桁の数字を検証し、RustのクリップボードAPIを呼ぶ。Linuxではクリップボードの所有権を保持する。

#### Scenario: 全角IDのコピー

- **WHEN** 先頭にゼロを含む全角5桁のルームIDをクリックする
- **THEN** 先頭のゼロを保持した半角5桁をコピーし、ブラウザーは開かない

#### Scenario: 参照先から得たID

- **WHEN** 募集の本文にIDがなく、有効な参照先からIDを得る
- **THEN** 「参照先のルームID」として表示し、本文のIDと同じ操作でコピーできる

### Requirement: 募集から雀魂を起動する

起動ボタンは以下の操作と有効状態を提供しなければならない（SHALL）。

募集カードにルームIDごとの「雀魂を起動」ボタンを表示する。クリックすると半角5桁のIDをコピーして、保存済みの起動設定で雀魂を開く。自動入室は行わず、ゲーム内の友人戦でIDを貼り付ける。締め切り・期限切れの募集では起動ボタンを無効にする。本文のIDをクリックする既存のコピー操作は維持する。起動失敗は画面に表示する。通知のクリックでは引き続きsurenecoを表示する。

#### Scenario: 有効な募集からの起動

- **WHEN** 有効な募集の「雀魂を起動」をクリックする
- **THEN** 半角5桁のIDをコピーして保存済みの設定で起動し、自動入室はしない

#### Scenario: 無効な募集

- **WHEN** 募集が締め切りまたは期限切れになる
- **THEN** 起動ボタンを無効にする

### Requirement: 起動方法の選択

起動方法と引数は以下の指定に従わなければならない（SHALL）。

起動方法は「既定ブラウザー」「Chrome / Edge」「指定アプリ」から選ぶ。既定は既定ブラウザーで [https://game.mahjongsoul.com/] を開く。Chrome / Edgeは実行ファイルの絶対パス、プロファイルのディレクトリー名（Default、Profile 1等）、必要ならユーザーデータディレクトリーの絶対パスを指定する。プロファイル名は表示名ではなくchrome://versionまたはedge://versionにあるプロファイルパスの末尾を使う。ブラウザーに--profile-directory、任意の--user-data-dir、固定のゲームURLを渡す。指定アプリは実行ファイルの絶対パスと任意の起動引数を指定する。Steam経由の場合はsteam.exeと-applaunch、対象ゲームのApp IDを指定できる。引数は一行に一つ入力し、空白を含む引数も引用符で囲まない。

#### Scenario: ブラウザープロファイル指定

- **WHEN** Chrome / Edgeの実行ファイルとプロファイルを設定して起動する
- **THEN** 指定のプロファイルと任意のユーザーデータディレクトリー、固定のゲームURLを引数として渡す

#### Scenario: 指定アプリの引数

- **WHEN** 空白を含む引数を一行に一つ入力する
- **THEN** 引用符の追加を要求せず、各行を一つの引数として扱う

### Requirement: 起動設定の保存と実行

起動要求は以下の保存済み設定と実行境界を守らなければならない（SHALL）。

起動設定はlauncher_mode、launcher_path、launcher_args、launcher_profile、launcher_user_data_dirとして既存の設定ファイルへ保存する。公開済みの設定にこれらの項目がない場合だけ既定値を補う。不正な値は保存前に拒否する。実行ファイルはRust側でシェルを介さず引数配列で起動し、作業ディレクトリーには実行ファイルの親を使う。起動要求はルームIDのみを受け取り、保存済み設定を使用する。起動先はsureneco終了後も継続する。

#### Scenario: 保存済み設定からの起動

- **WHEN** ルームIDだけを指定して起動を要求する
- **THEN** 保存済み設定を用い、シェルを介さず引数配列で実行して実行ファイルの親を作業ディレクトリーにする

### Requirement: 起動直後の結果確認

指定ブラウザー・アプリの起動結果は以下の条件で判定しなければならない（SHALL）。

指定ブラウザー・アプリは起動後1秒以内の異常終了も起動失敗として扱い、実行ファイルのパスと終了コードまたはシグナルを画面に表示する。既存プロセスへ起動要求を渡して正常終了する場合は成功とする。1秒経過後は起動処理を完了し、ゲームの終了を待たない。この確認はゲーム画面の表示やログイン完了を保証しない。

#### Scenario: 起動直後の異常終了

- **WHEN** 起動したプロセスが1秒以内に異常終了する
- **THEN** 実行ファイルのパスと終了コードまたはシグナルをエラーとして表示する

#### Scenario: 既存プロセスへの引き継ぎ

- **WHEN** 起動要求を既存プロセスへ渡して正常終了する
- **THEN** 起動成功として扱う

#### Scenario: 継続するプロセス

- **WHEN** 起動後1秒を経過してプロセスが動作している
- **THEN** 起動処理を完了し、ゲーム終了を待たない
