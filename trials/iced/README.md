# Iced比較試作

Tauri版を置き換えず、Windows／Linux向けUIをIcedで試す。現行のRustライブラリーを`default-features = false`で再利用し、HTTP制約、保存、QuickJS上のTypeScript監視コアは同じものを使う。完全なRust判定コアへの移植ではなく、WebView／ReactとIcedのUI実装差を調べる試作である。

## 実装範囲

- スレッド一覧取得・手動／定期更新、監視トグル、募集一覧、ルームIDコピー、スレッドを開く。
- 現行コアで検証・保存する通常の設定画面（更新間隔、表示期間、検出・除外正規表現、板URL、NG／許可リスト、雀魂の起動方法）。試作用の保存先を分離し、本番の`sureneco`設定を上書きしない。未保存の編集は定期更新で失わず、保存失敗でも保持する。
- 設定の「保存」は未保存の変更がある場合だけ表示し、入力を保存済みの値に戻すと非表示になる。「デフォルトに戻す」で起動設定を含む表示中の設定を共通コアの既定値へ戻す。反映には「保存」が必要で、保存失敗時は入力と保存ボタンを保持する。監視対象・非表示の将来設定・外観・ウィンドウ状態はデフォルト復元の対象外。外観は従来どおり即時に自動保存する。
- 設定フォームの8テストに成功し、Linux実画面で保存ボタンの出現・元の値への復帰時と保存成功後の非表示、デフォルト復元の保存待ちと保存後の反映、検証エラー時の入力保持、保存後の連続入力、400×600での操作を確認した（2026/11/12）。通知などの表示が増減しても設定フォームの状態を保持する。Windows x64版もビルド済みで、実機確認は未実施。画面証跡は`release/iced-settings-actions-20261112/`（Git管理外）。
- Tauri版と同じ「既定ブラウザー」「Chrome / Edge（プロファイル指定）」「指定アプリ（雀魂・Steamなど）」を提供する。Chrome / Edgeは実行ファイルと任意のプロファイル名・ユーザーデータディレクトリーを指定する。指定アプリは実行ファイルと1行1引数を指定し、Steamでは`-applaunch`と対象ゲームのApp IDを別々の行に入力する。保存済み設定を使い、募集ごとの「雀魂を起動」で検証済みルームIDをコピーしてから起動する。入室はゲーム内でIDを貼り付ける。満員・期限切れの募集では起動を無効化し、コピーは引き続き利用できる。
- 起動処理はTauri版と共通のRustモジュールを使用し、シェル展開せず引数を個別に渡す。クリップボード失敗時は起動しない。指定アプリの起動失敗・直後の異常終了を画面に表示し、UIを通信・プロセス待ちで停止させない。自動入室・ゲームの導入・Steam App IDの自動取得は行わない。
- 共通起動処理2テスト・設定フォーム10テストに成功し、Tauri版のrelease型確認とWindows x64版ビルドも成功（2026/11/12）。Linux実GUIから、指定アプリ／Steam形式の引数、ブラウザープロファイル、既定ブラウザーURL、起動前の実クリップボード内容、保存・再起動、終了コード7のエラー、満員／期限切れの無効化、400×600の操作を確認した。記録用実行ファイルと試験用`xdg-open`を使用した検証であり、雀魂・Steam・Chrome／Edge本体とWindows実機は未検証。画面と起動記録は`release/iced-launcher-20261112/`（Git管理外）。
- ネットワークとQuickJSは専用スレッドに置き、UIイベントループを止めない。通信・保存・通知の失敗は表示する。
- トレイから表示・更新・終了でき、利用できる環境ではウィンドウを閉じても監視を続ける。トレイを利用できない場合は閉じる操作で終了し、到達不能なバックグラウンドプロセスを残さない。画面にも明示的な終了操作を設ける。
- 同じ設定フォルダーでは1プロセスだけ起動する。OSのファイルロックを起動直後から終了まで保持し、トレイ常駐中も二重起動を防ぐ。2個目は監視・通知・ウィンドウを開始せず終了する（既存ウィンドウの自動表示は行わない）。通常終了・異常終了でロックは自動解放される。`.instance.lock`は残っていて正常であり、実行中に削除しない。異なる`--data-dir`は独立して起動できる。
- 多重起動の回帰テスト3件で、別プロセスとの競合、異常終了後の再取得、通常解放、独立した設定フォルダー、実際のファイルエラーを確認した。Linux実行ファイルでも、ロック中の設定への起動がGUI初期化前に正常終了し、保存内容を変更しないことを確認。Windows x64版はビルド済みで、実機確認は未実施（2026/11/12）。旧版はこのロックを持たないため、差し替え前に起動済みの旧版をすべて「終了」する。
- ウィンドウの通常時の位置・サイズと最大化状態を専用設定フォルダーの`window-state.json`へ保存し、次回起動時に復元する。最小化・トレイ非表示で通常サイズを上書きしない。移動・リサイズはまとめて保存し、終了時にも保存する。保存内容が不正なら既定サイズで起動し、位置を取得できない環境ではサイズだけを保存する。
- 保存の回帰テスト7件が成功。LinuxのXvfb＋Openboxで、移動だけの保存、通常位置・サイズの再起動復元、最大化復元、最小化中の値保持、変更直後の終了保存、静止中にファイルを書き直さないことを確認した（2026/11/12）。Windows x64版もビルド済み。Windows実機・混在DPI環境は未検証。画面・記録は`release/iced-window-state-20261112/`（Git管理外）。
- モニター構成変更後の画面外座標の自動補正は行わない。位置をリセットしたい場合はアプリを終了して専用設定フォルダーの`window-state.json`だけを削除する。監視設定の`state.json`は削除しない。
- OS通知はWindowsの専用アプリIDとLinuxのD-Bus通知サーバーに対応する。接続・登録失敗は利用不可として表示する。自動起動・自動更新は対象外。本番Tauri版・PHP版の設定や登録は変更しない。
- 見た目はTauri版に合わせ、緑のアクセントとライト／ダークの配色を使う。「設定」の「ダークモード」で即時に切り替え、専用設定フォルダーの`appearance.json`へ自動保存する。初期値はライトでOS連動は行わない。保存失敗時は元の配色を保ちエラーを表示し、不正な保存内容ではライトで起動してエラーを表示する。監視設定の保存・未保存編集とは独立して扱う。「スレッド」「友人戦募集」「設定」をタブで切り替え、候補と募集を横に並べない。保存先・接続情報は設定内の詳細へまとめる。設定項目は用途別カードに分ける。監視・保存・通知の処理は変更しない。
- ダークモードは保存テスト2件に成功し、Linux仮想画面で3タブ、ライトへの復帰、未保存入力の保持、終了・再起動後の復元、保存失敗時の配色維持、不正ファイル時のエラー、400×600での設定操作領域を確認した（2026/11/12）。Windows x64版もビルド済みで、Windows実機の表示は未確認。画面証跡は`release/iced-dark-mode-20261112/`（Git管理外）。通知サーバーは試験用に無効化しており、画面の通知利用不可表示はその結果。
- フォントはTauri版の優先指定と同じ「Noto Sans JP」を使い、細すぎるという利用者報告に対応してMedium（500）をアプリへ組み込む。文字サイズは14pxのまま、本文・ボタン・入力欄の既定ウェイトを一段太くする。OS別のフォント指定・追加インストール・実行時ダウンロードは不要。描画エンジンによるアンチエイリアス等の差は残る。
- フォントは[公式配布](https://github.com/notofonts/noto-cjk/blob/main/Sans/SubsetOTF/JP/NotoSansJP-Medium.otf)の無改変OTF（約4.5MB）を`assets/fonts/`へ配置し、SIL Open Font License 1.1に従う。Regularは同梱せず、二重に保持しない。配布ZIPには著作権表示とライセンス全文の`NotoSansJP-OFL.txt`も含める。別途パッケージを作る場合もフォントのライセンスを同梱する。
- Medium原本のGit blob（`490cc708a90767e9a9c867e147df33a8c62c1f6d`）とウェイト500を確認。Fontconfigのシステムフォント一覧を空にしたLinux実画面で、本文・ボタン・入力欄、ライト／ダーク、400×600の表示を確認した（2026/11/12）。Windows x64版はビルド済みで、実機表示は未確認。画面証跡は`release/iced-font-medium-20261112/`（Git管理外）。
- Windowsのrelease版はGUIサブシステムを使い、余分なコンソールウィンドウを開かない。タブ切替時は本文を先頭へ戻し、設定を下までスクロールした位置を募集一覧へ持ち越さない。日時表示のタイムゾーンはUTCと明記する。
- 外観変更はLinux仮想画面の1120×820／400×600で確認した。3タブ、監視オン／オフ、設定保存、ルームIDの実コピー、詳細の開閉、タブ切替時のスクロール復帰を操作確認し、Windows x64実接続用releaseビルドにも成功。Windows実機の表示は未検証。画面証跡は`release/iced-visual-20261111/`（Git管理外）。

## 起動

リポジトリーのルートで実行する。通常利用では比較用featureを付けず、実際の5chへ接続する。

```sh
pnpm build
CARGO_TARGET_DIR="$PWD/src-tauri/target" \
  cargo run --release --manifest-path trials/iced/Cargo.toml
```

初回は候補を取得後に監視ボタンを有効にする。設定は「設定」で編集し、保存時に既存コアの値・正規表現・URL・起動設定の検証を受ける。NG／許可リストと起動引数は1行1項目。雀魂の起動方法を保存してから、募集中のルームIDに対応する「雀魂を起動」を押す。既定の保存先はOSの設定ディレクトリー内の`sureneco-iced`。別の空ディレクトリーを使う場合は末尾に`-- --data-dir /absolute/trial-directory`を付ける。本番設定のコピーや移行は不要で、`config-location.json`による保存先切替も読み込まない。

Linuxでは通常のデスクトップセッションが必要で、日本語フォントは同梱する。SSHで`DISPLAY`がない場合、そのままではGUIを起動できない。Windows向け実機検証・インストーラー作成はこの試作に含めない。

### 常駐と通知

- トレイメニューは「表示」「更新」「終了」。Windowsでは左クリックでも表示する。LinuxのAppIndicatorはクリックでホスト側のメニューを開く方式で、「表示」を選ぶ。
- LinuxはGTK 3の開発ファイル、Ayatana AppIndicator 3（または旧AppIndicator 3）の実行時ライブラリー、セッションD-Bus、StatusNotifier対応トレイホストが必要。GNOMEではAppIndicator対応拡張等が必要になる場合がある。旧XEmbed専用トレイは対象外。
- ホストと自分のアイコンの登録を確認してから「閉じると常駐」に切り替える。確認中・利用不可では閉じると終了する。常駐中にホストを失った場合は画面を再表示する。ウィンドウ内の「終了」とトレイの「終了」は通信・保存を待ってプロセスを終了する。
- Windows通知は`io.github.sakots.sureneco.iced`を現在ユーザーの`Software\Classes\AppUserModelId`へ登録し、ユーザーのスタートメニューに同じAppUserModelIDを持つ`sureneco-iced.lnk`を作成する。ZIP版を別フォルダーへ移した場合も起動時にリンク先を現在のEXEへ更新する。本番Tauri版のアプリID・ショートカットは使わない。Windows側で通知が無効の場合も利用不可を表示する。
- 自動起動・自動更新はまだ提供しない。Windowsの実通知・トレイの実機確認は別途必要。
- `0x80070490`は通知ID付きショートカットの追加だけでは解消しなかった。未パッケージアプリで初回送信前に`ToastNotifier.Setting`を取得すると失敗するため、[Microsoft.Toolkitの実装](https://github.com/CommunityToolkit/WindowsCommunityToolkit/blob/main/Microsoft.Toolkit.Uwp.Notifications/Toasts/Compat/ToastNotifierCompat.cs)に合わせ、ポップアップ・音を抑えた有効期限15秒の初期登録通知を送信して自分の履歴だけ削除し、その後に通知設定を取得する。登録・送信・履歴削除・設定取得の失敗と、ユーザーが通知を無効にした状態は引き続きエラーとして扱う。
- ショートカット追加時は通知XMLの2テストが成功した。初回送信順序の修正後も、Windows用回帰テストのクロスコンパイルとWindows x64 releaseビルドに成功。通知初期化エラーの解消は利用者のWindows環境で確認済み。Windows用テストの実行・募集通知の実表示は未確認。

## 比較条件

両方をreleaseビルドし、同じ監視コア・同じ設定・同じローカルの板／dat応答を使う。応答差を排除する比較専用Cargo feature `comparison-fixture`は通常の配布には含めない。フィクスチャを有効にした場合は許可済みの板URLだけをローカルから読み、読み込み失敗を実ネットワークへフォールバックさせない。

測定はLinuxのプロセスツリー全体を対象にする。TauriのWebKit子プロセスを除外せず、RSSとPSSを区別し、UIの起動待ちと安定後のメモリを同じ手順・時間で記録する。実行順・回数・画面サイズ・ビルド形式・描画方式も記録する。単一プロセスのRSS、debugとreleaseの混在、Icedの画面なしモードとTauriのGUIの比較は行わない。

SSHにGUI表示先がない場合、仮想ディスプレイでの結果はその旨を明記する。実デスクトップ・実GPU・Windowsでの値と同一視しない。GUIが起動しなかった場合はメモリ比較の成功とは扱わない。

## 測定コマンド（Linux）

```sh
pnpm build
cargo build --release --manifest-path src-tauri/Cargo.toml --features comparison-fixture,tauri/custom-protocol
CARGO_TARGET_DIR="$PWD/src-tauri/target" \
  cargo build --release --manifest-path trials/iced/Cargo.toml --features comparison-fixture
python3 scripts/compare-native-ui.py \
  --tauri "$PWD/src-tauri/target/release/sureneco" \
  --iced "$PWD/src-tauri/target/release/sureneco-iced" \
  --display "$DISPLAY" --display-kind desktop \
  --output "$PWD/release/iced-comparison.json"
```

`tauri/custom-protocol`は、Tauri CLIを経由せずCargoで直接配布相当のHTMLを埋め込むために必要。付けない場合は開発用URLを参照して画面が表示されず、比較に使えない。

既存の出力ファイルには上書きしない。通常ビルドしか指定されていない、GUIがない、PSSを読めない、板／datを読めない場合は測定失敗にする。実行ごとに専用HOME／XDG領域を作り、同じ3候補・1監視スレッド・4投稿を投入する。許可ワッチョイを不一致にして両方のOS通知を抑え、本番の端末・通知設定は使わない。生データと実行ログは指定JSONとその`.artifacts`ディレクトリーに保存する。

既定は順序を交互にした各3回、ウィンドウ表示後2秒待って10秒測定する。起動時間は最初にウィンドウが表示された時刻で、初回描画完了の計測ではない。RSSは共有ページを重複計上するためPSSも併記する。ピークは安定待ち後のサンプル最大値で、起動時ピークではない。実行ファイルサイズには共有ライブラリー・フォント・インストーラーを含めない。画面構成はTauriの初期画面とIcedの候補／募集併記で異なり、製品機能の完全同等比較ではない。

## 実測結果（2026/11/11）

以下はJSON設定・常駐なしの初期試作の参考値。実用化で追加した画面・トレイ・通知対応を含む現行版の測定値ではない。

Linux x86_64、Xvfb 1280×900、両アプリのウィンドウ1120×820。Icedはtiny-skia、TauriはWebKitGTK。`DISPLAY=:121 LIBGL_ALWAYS_SOFTWARE=1 WEBKIT_DISABLE_DMABUF_RENDERER=1`を設定した`dbus-run-session`内で、上記測定に`--display-kind virtual`を指定した。GPU描画・Windows・実デスクトップの結果ではない。

各3回とも板／dat読み込み・画面表示・PSS取得に成功。値は各実行の中央値をさらに3回で中央値にしたもの。

| 指標 | Tauri | Iced |
| --- | ---: | ---: |
| プロセスツリーRSS | 389.61 MiB | 60.81 MiB |
| プロセスツリーPSS | 200.83 MiB | 49.58 MiB |
| ウィンドウ表示まで | 0.655秒 | 0.077秒 |
| 実行ファイル | 28.78 MiB | 22.25 MiB |
| 最大プロセス数（各回の中央値） | 6 | 1 |

この条件ではPSSが75.3%少ない。ただしトレイ等の機能差に加え、独立したCargo.lockによる依存パッチの差もある（Tauri／Icedの順にserde_json 1.0.151／1.0.154、notify-rust 4.18.2／4.19.0）。差の全量をWebViewだけの寄与とは断定しない。起動時間はウォーム／コールドキャッシュを分離していない。

生データはローカルの`release/iced-comparison-20261111-software.json`、画面証跡は`release/iced-prototype-visual-20261111/`に保存した（生成物としてGit管理外）。配布用プロトコルを付けない初回ビルドの画面未表示は失敗として除外し、上表に混ぜていない。

仮想画面で日本語表示、候補3件・募集表示、監視オン／オフ保存、19秒設定の拒否、21秒設定の保存・正常終了・再起動後の保持、ルームID `34567`の実クリップボードコピー、募集期限切れと締め切りの区別、通知サーバー接続失敗表示を確認した。共通コアのRustテストは27件成功。ブラウザー起動先の実操作、OS通知の実配信、Windowsでの動作は未検証。
