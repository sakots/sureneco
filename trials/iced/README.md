# Iced比較試作

Tauri版を置き換えず、Windows／Linux向けUIをIcedで試す。現行のRustライブラリーを`default-features = false`で再利用し、HTTP制約、保存、QuickJS上のTypeScript監視コアは同じものを使う。完全なRust判定コアへの移植ではなく、WebView／ReactとIcedのUI実装差を調べる試作である。

## テスト版の配布

Iced版のバージョンは現行製品と同じ**0.10.1**とし、[既存v0.10.1](https://github.com/sakots/sureneco/releases/tag/v0.10.1)へ追加配布する。既存タグ・Tauri版添付・`latest.json`・既存チェックサムは変更しない。タグのソースアーカイブも従来のままであり、Iced版のソースコミットは同梱の`BUILD-INFO.json`を参照する。

- Windows x64：`sureneco-iced_v0.10.1_win-x64.zip`を展開し、`sureneco-iced.exe`を実行する。
- Linux x64：`sureneco-iced_v0.10.1_linux-x64.tar.gz`を展開し、GUIセッション内で`./sureneco-iced`を実行する。Ubuntu 26.04.1でビルドしたglibc 2.43以上向けのバイナリーで、古いUbuntuには対応しない。DEB／AppImageではなく、GTK 3と、トレイ利用時はAyatana AppIndicator 3・対応ホストが必要である。
- `sureneco-iced_v0.10.1_SHA256SUMS.txt`で照合する。アーカイブにはフォントライセンス、MITライセンス、起動案内、ソースコミットを記したビルド情報を同梱する。比較用フィクスチャは含めない。

Tauri版との設定共有・自動移行・自動更新はしない。起動済みの旧Iced版を「終了」してから差し替える。Windows実機での最終配布物確認は未実施である。

公開前にIced版36テスト・共通Rustライブラリー27テスト、両OSのreleaseビルド、整形・差分チェック、Linuxの`--help`起動と共有ライブラリー解決を確認した。両版とも比較フィクスチャを含めていない。

## 実装範囲

- スレッド一覧取得・手動／定期更新、監視トグル、募集一覧、ルームIDコピー、スレッドを開く。
- 現行コアで検証・保存する通常の設定画面（更新間隔、表示期間、検出・除外正規表現、板URL、NG／許可リスト、雀魂の起動方法）。試作用の保存先を分離し、本番の`sureneco`設定を上書きしない。未保存の編集は定期更新で失わず、保存失敗でも保持する。
- 設定の「保存」は未保存の変更がある場合だけ表示し、入力を保存済みの値に戻すと非表示になる。「デフォルトに戻す」で起動設定を含む表示中の設定を共通コアの既定値へ戻す。反映には「保存」が必要で、保存失敗時は入力と保存ボタンを保持する。監視対象・非表示の将来設定・外観・ウィンドウ状態はデフォルト復元の対象外。外観は従来どおり即時に自動保存する。
- 「設定フォルダー」で絶対パスを入力し「保存先を変更」を押すと、保存済み設定・監視対象・取得済みレス番号の`state.json`をコピーし、以後の読み書き先を切り替える。旧ファイルは残す。未保存の設定入力は保持するがコピーには含めず、変更後の「保存」で反映する。既存の`state.json`や使用中の保存先は上書きしない。失敗時は元の保存先・ロックを保持する。
- 次回起動時はIced専用の起動基準フォルダー内の`config-location.json`から保存先を復元する。既定の基準はOS設定ディレクトリー内の`sureneco-iced`で、`--data-dir`を指定した場合はそのフォルダーが基準となる。外観の`appearance.json`とウィンドウの`window-state.json`は基準フォルダーに残す。Tauri本番の保存先ポインターを自動探索・移行しない。

## アイコン素材の再生成

ImageMagickの`convert`とPythonのPillowを開発環境に用意し、リポジトリーのルートで`python3 scripts/generate-iced-icons.py`を実行する。`app.svg`からPNG・RGBA・ICOを再生成する。生成済み素材はGit管理するため、通常のビルド・実行に画像変換ツールは不要。Windowsのリソースコンパイルに失敗した場合はアイコンなしで配布せず、ビルドを中止する。

## 起動

リポジトリーのルートで実行する。通常利用では比較用featureを付けず、実際の5chへ接続する。

```sh
pnpm build
CARGO_TARGET_DIR="$PWD/src-tauri/target" \
  cargo run --release --manifest-path trials/iced/Cargo.toml
```

初回は候補を取得後に監視ボタンを有効にする。設定は「設定」で編集し、保存時に既存コアの値・正規表現・URL・起動設定の検証を受ける。NG／許可リストと起動引数は1行1項目。雀魂の起動方法を保存してから、募集中のルームIDに対応する「雀魂を起動」を押す。既定の起動基準フォルダーはOS設定ディレクトリー内の`sureneco-iced`。別の独立した基準を使う場合は末尾に`-- --data-dir /absolute/trial-directory`を付ける。実データの保存先は画面から変更でき、基準内の`config-location.json`を読む。参照先が不正・利用不能な場合は起動を中止し、既定の空設定へ黙って戻らない。本番設定のコピーや移行は不要。

Linuxでは通常のデスクトップセッションが必要で、日本語フォントは同梱する。SSHで`DISPLAY`がない場合、そのままではGUIを起動できない。Windows向け実機検証・インストーラー作成はこの試作に含めない。

### 常駐と通知

- トレイメニューは「表示」「更新」「終了」。Windowsでは左クリックでも表示する。LinuxのAppIndicatorはクリックでホスト側のメニューを開く方式で、「表示」を選ぶ。
- LinuxはGTK 3の開発ファイル、Ayatana AppIndicator 3（または旧AppIndicator 3）の実行時ライブラリー、セッションD-Bus、StatusNotifier対応トレイホストが必要。GNOMEではAppIndicator対応拡張等が必要になる場合がある。旧XEmbed専用トレイは対象外。
- ホストと自分のアイコンの登録を確認してから「閉じると常駐」に切り替える。確認中・利用不可では閉じると終了する。常駐中にホストを失った場合は画面を再表示する。ウィンドウ内の「終了」とトレイの「終了」は通信・保存を待ってプロセスを終了する。
- Windows通知は`io.github.sakots.sureneco.iced`を現在ユーザーの`Software\Classes\AppUserModelId`へ登録し、ユーザーのスタートメニューに同じAppUserModelIDを持つ`sureneco-iced.lnk`を作成する。ZIP版を別フォルダーへ移した場合も起動時にリンク先を現在のEXEへ更新する。本番Tauri版のアプリID・ショートカットは使わない。Windows側で通知が無効の場合も利用不可を表示する。
- 自動起動・自動更新はまだ提供しない。Windowsの実通知・トレイの実機確認は別途必要。
- `0x80070490`は通知ID付きショートカットの追加だけでは解消しなかった。未パッケージアプリで初回送信前に`ToastNotifier.Setting`を取得すると失敗するため、[Microsoft.Toolkitの実装](https://github.com/CommunityToolkit/WindowsCommunityToolkit/blob/main/Microsoft.Toolkit.Uwp.Notifications/Toasts/Compat/ToastNotifierCompat.cs)に合わせ、ポップアップ・音を抑えた有効期限15秒の初期登録通知を送信して自分の履歴だけ削除し、その後に通知設定を取得する。登録・送信・履歴削除・設定取得の失敗と、ユーザーが通知を無効にした状態は引き続きエラーとして扱う。
- ショートカット追加時は通知XMLの2テストが成功した。初回送信順序の修正後も、Windows用回帰テストのクロスコンパイルとWindows x64 releaseビルドに成功。通知初期化エラーの解消は利用者のWindows環境で確認済み。Windows用テストの実行・募集通知の実表示は未確認。

## 比較条件

両方をreleaseビルドし、同じ監視コア・同じ設定・同じローカルの板／dat応答を使う。応答差を排除する比較専用Cargo feature `comparison-fixture`は通常の配布には含めない。フィクスチャを有効にした場合は許可済みの板URLだけをローカルから読み、読み込み失敗を実ネットワークへフォールバックさせない。

測定はLinuxのプロセスツリー全体を対象にする。TauriのWebKit子プロセスを除外せず、RSSとPSSを区別し、UIの起動待ちと安定後のメモリを同じ手順・時間で記録する。実行順・回数・画面サイズ・ビルド形式・描画方式も記録する。単一プロセスのRSS、debugとreleaseの混在、Icedの画面なしモードとTauriのGUIの比較は行わない。

SSHにGUI表示先がない場合、仮想ディスプレイでの結果はその旨を明記する。実デスクトップ・実GPU・Windowsでの値と同一視しない。GUIが起動しなかった場合はメモリ比較の成功とは扱わない。

```sh
  --tauri "$PWD/src-tauri/target/release/sureneco" \
  --iced "$PWD/src-tauri/target/release/sureneco-iced" \
  --display "$DISPLAY" --display-kind desktop \
  --output "$PWD/release/iced-comparison.json"
```

`tauri/custom-protocol`は、Tauri CLIを経由せずCargoで直接配布相当のHTMLを埋め込むために必要。付けない場合は開発用URLを参照して画面が表示されず、比較に使えない。

既存の出力ファイルには上書きしない。通常ビルドしか指定されていない、GUIがない、PSSを読めない、板／datを読めない場合は測定失敗にする。実行ごとに専用HOME／XDG領域を作り、同じ3候補・1監視スレッド・4投稿を投入する。許可ワッチョイを不一致にして両方のOS通知を抑え、本番の端末・通知設定は使わない。生データと実行ログは指定JSONとその`.artifacts`ディレクトリーに保存する。

既定は順序を交互にした各3回、ウィンドウ表示後2秒待って10秒測定する。起動時間は最初にウィンドウが表示された時刻で、初回描画完了の計測ではない。RSSは共有ページを重複計上するためPSSも併記する。ピークは安定待ち後のサンプル最大値で、起動時ピークではない。実行ファイルサイズには共有ライブラリー・フォント・インストーラーを含めない。画面構成はTauriの初期画面とIcedの候補／募集併記で異なり、製品機能の完全同等比較ではない。
